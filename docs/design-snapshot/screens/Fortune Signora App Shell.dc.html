The Fortune Signora application shell

The shell is the only part of the product every user sees on every visit, so it is specified once and never negotiated per module. It holds a fixed frame — banners, rail, top bar, filter strip, content, utility panel — and a fixed set of transient surfaces that open over it. Modules own the content region and nothing else.

02

Left navigation

232px expanded, 56px collapsed, full height, on the rail ground with a single hairline to content. Nine destinations, two levels, ordered along the revenue funnel. Items are 32px pills; the active item is a brand-tint fill with a 600-weight label and a coloured icon. Second-level items appear only under the open parent and indent to 30px. Counts are live but never a badge — a badge means "unread", a count means "how many".

03

Workspace switcher

Pinned to the top of the rail, because switching workspace is a change of everything below it. The trigger states the workspace, its plan and its region. The menu groups by organisation, shows role and environment per workspace, searches above six entries, and always ends with the two administrative escapes. Switching preserves the current route when the destination has it, and lands on Home when it does not — it never drops the user on an error.

04

Top navigation

56px, surface-coloured, sticky, one hairline at the bottom. Left: breadcrumb only. Right, in fixed order: search, system status, notifications, help, account. The order never changes between modules, because muscle memory in the top-right corner is the single most valuable thing a shell can offer. Module actions live in the page header, one level below.

05

Breadcrumbs

Mandatory below the first level, because most sessions start from a deep link in Slack or email. They mirror the data hierarchy, not the click path. Past four levels the middle collapses into an ellipsis menu; the last crumb is the current record, is not a link, and carries its status dot. Crumbs truncate from the middle out — the current record is the last thing to lose characters.

06

Global filters

A 46px strip directly under the top bar holding the four dimensions every module shares: period, region, segment, owner. Module-local filters live in the module's own toolbar and are visually distinct — global filters are tinted, local filters are outlined. Global scope survives navigation, serialises to the URL, and can be saved as a named view. Nothing here is ever hidden behind a collapse.

Banners & system status

At most two banners are ever stacked: one environment, one commercial. System status is a persistent pill in the top bar rather than a banner — degradation is a fact about the product, not an interruption, and it expands into detail on click.

08

Global search

There is exactly one global search and it is the palette. The top-bar field is a doorway, not a second search: clicking it or pressing ⌘K opens the same surface with the same behaviour. Results are typed, grouped and ranked by recency-weighted relevance, with the record's key facts on the row so the user rarely needs to open the wrong one. A natural-language question routes to the assistant instead of returning rows.

13

Right utility panel

A docked 300–360px column for context that accompanies the content: insights, activity, notes, and the record preview a table row produces. It is non-modal, it pushes rather than overlays, and its open state is remembered per module per user. It never holds a task — anything with a Save belongs in the context drawer.

14

Context drawer

Modal, right-hand, 480 / 640 / 800px, for a task with a definite end: edit a record, build a filter, review agent output, complete a workflow step. It has a header with the object name, a scrolling body, and a pinned footer holding the primary action. Escape closes only when nothing would be lost; otherwise it asks. Drawers never stack — a second task replaces the first, with a breadcrumb back to it.

Keyboard shortcuts

Two families: chords with ⌘ for surfaces, and Vim-style sequences with G for navigation. ? opens the reference from anywhere. Every shortcut is listed beside its command in the palette, which is how users discover them — a cheat sheet nobody opens is not a feature.

16

Global loading

Three tiers, chosen by what is actually unknown. Cold boot paints the shell chrome immediately and skeletons only the content region — the frame is never blank, because the frame is the same on every route. Route changes keep the shell and skeleton the content. In-place refreshes show a 2px bar under the top bar and dim stale figures to 60%; they never cover data that is already readable.

17

Error pages

Errors render inside the shell whenever the shell itself is healthy — the rail, top bar and workspace stay, so the user is never stranded. Only a failed boot or a lost session takes the full page. Every error states what happened, what it means for their data, one route forward, and a copyable correlation ID. No apologies, no cartoons, no dead ends.

19

Multi-workspace behaviour

A workspace is the hard boundary of data, permission and configuration. The shell never mixes two workspaces in one view; it makes moving between them cheap and unmistakable instead. Every workspace-scoped surface — search, notifications, filters, the assistant — is labelled with the workspace it belongs to whenever more than one is available to the user.

20

Responsive behaviour

The shell yields in a fixed order as width disappears: utility panel first, then the rail's labels, then the rail itself, then the filter strip, and only then does content reflow. Data is the last thing to change and is never removed — a column becomes a card line, never a hidden field. Below 640px the shell is a review tool: read, approve, comment, ask. It is not where a territory plan gets built.

The shell is a contract, not a template

A module receives one region and four guarantees: the frame will not move, the global scope is already applied, the transient surfaces already exist, and the keyboard model is already learned. In exchange it may not add chrome, invent a second search, place actions in the top bar, or open its own floating panels. Every capability a module thinks it needs from the shell is either already here or becomes an amendment to this document.
