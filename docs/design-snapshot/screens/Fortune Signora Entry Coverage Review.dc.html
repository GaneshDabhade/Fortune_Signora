Can every Entry destination be built without inventing behaviour?

Not yet. Twenty-four routing rules resolve to nineteen distinct destinations. Eleven are fully covered by documents already shipped, five need a named section added to a document that exists, and three require new companion specifications. One architectural change — the Executive Dashboard becoming a composition rather than a destination — creates contradictions in four shipped files that must be corrected before anything is built.

01 · Verdict on the Entry document
✓

Leave it as it is, plus one column

The Entry document is correctly scoped and should not absorb a single destination screen. The only change it needs is a "Specified in" column on the rules table naming the companion document for each destination — twenty-four cross-references, no new prose, no new screens. That column is what makes the separation enforceable: a rule with no named document is a gap, visible in the table rather than discovered in a sprint.
