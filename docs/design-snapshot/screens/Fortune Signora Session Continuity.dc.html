Session Continuity

What survives an interruption, and what the person sees while it is being restored. Five shipped documents promise preservation in passing — drafts through a 500, filters and scroll through entry, view state in the URL, an offline queue in the profile — and none defines the model. This document defines it once. It owns restoration; it does not own routing, which remains with Authenticated Entry.

01 · Purpose, scope & non-goals

Purpose

Make continuity deterministic. Given a boot condition, the person and the implementation must be able to state — before it happens — which frame renders, what is restored, what is discarded, and what the screen says. Non-determinism here is not a polish defect: a draft that survives sometimes is worse than one that never survives, because people stop trusting the product with unsaved work.

The one-line contract
Signora never silently loses typed input, and never silently claims to have kept it. Anything preserved is labelled with when it was captured; anything discarded is named at the moment of discard.

Four tiers. Everything preservable belongs to exactly one.
