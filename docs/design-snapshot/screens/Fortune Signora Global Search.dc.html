Enterprise search One doorway · two exits · never a second search box

Search that answers before you finish typing

Eight million records, four object types, one keystroke away. Speed here is not a performance target, it is the interaction model: results render on the first character from a local index, the network only ever refines what is already on screen, and nothing the user sees is allowed to move once it has appeared.

02

AI & natural-language search

The same input handles both. A name is lookup; a question is retrieval. The classifier runs locally on the first three words, and when a query reads as a question the top group becomes an answer — with citations, a result set the answer was computed from, and a translation of the question into the filters it applied, so the user can correct the interpretation instead of rephrasing blindly.

Full results, facets & filters

Pressing Enter on the query itself — rather than on a result — opens the full results page. Facets sit in a 240px rail with live counts and never reorder while the user reads them; a facet with zero matches stays visible at 45% so the absence is information. Filters are chips above the list, distinguishable from the global scope chips of the shell: search filters are outlined, scope is tinted.

06

Empty input: pinned, recent, suggested

The most-used state of any search is the one before typing, so it is designed as a launcher rather than a blank field. Pinned items sit first because the user chose them; recents next because they are usually the answer; suggestions last, generated from what changed since the user's last visit and always dismissible.

07

Saved & monitored searches

A saved search stores the query, the filters and the sort — not the results. Monitoring turns it into a standing question: it runs on a schedule, and when the result set or an AI answer changes materially it produces a notification rather than an email nobody reads. This is how search becomes a workflow instead of an errand.

08

Ranking

Ranking is explainable on purpose: a rep who cannot predict the order stops trusting the first result. Within a group, score is a weighted sum of six factors, and the dominant one is shown on the row when it is not lexical. Recency and ownership beat raw text score — the record you touched yesterday is almost always the one you meant.

09

Keyboard navigation

Search is a keyboard surface first; the mouse is the fallback. The cursor never leaves the input, arrow keys move a virtual selection, and every destination has a modifier. Nothing requires a click, and the hand never has to travel.

10

Loading, no results, errors

Because the first paint comes from a local index, a true loading state is rare and short — so it is a 2px bar under the input, not a skeleton over the list. No-results is the state that earns the most design: it states the query, shows which filter is doing the excluding, and offers the widest single change that would help.
