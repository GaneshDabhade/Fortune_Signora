# The Coordination source

**Read `coordination.toml`. That is the whole of it.**

> ## **Every implementation lane learns what to build next from this ref, and from nothing else.**

**Fetch it:**

```
git fetch origin coordination
git show origin/coordination:coordination.toml
```

⛔ **Do not poll `lane-c-sync`, `lane-qe`, `integration` or commit history to find work.** ⚡ **This ref exists so that planning information does not have to travel through the release pipeline** — [479](https://github.com/GaneshDabhade/Fortune_Signora/blob/integration/docs/architecture/479-coordination-architecture.md), ratified 2026-08-07.

## What it holds

| | |
|---|---|
| `[meta]` | When it was generated and from which commit — ⚡ **so a lane can see how old its instruction is** |
| `[lane.*]` | **`current`, `next`, `next_after_that`** · claimable · in flight · blocked · utilization · idle prediction · dependency wait · critical path |
| `[[task]]` | Every open row: state · lane · `depends_on` · `unblocks` · `next_owner` · `critical_path` · `estimated_ready` · `waiting_for` |

## What it is not

⛔ **Not editable.** **It is generated by `infra/coordination.py` from `BACKLOG.md`, `modules.toml` and `LANE_COORDINATION.md`, which remain authoritative.** **Editing this file makes it wrong rather than making it true.**

⛔ **Not a replacement for Startup.** **A lane still reads `BUGS.md` and `LANE_COORDINATION.md` for awareness** (`CLAUDE.md` §20e steps 3 and 5). ⚡ **What changed is that *what to build next* no longer requires them.**

⛔ **Not the execution record.** **A claim still goes to `integration` by the Task Claim Protocol, and QE still validates, certifies, integrates and promotes.** **Planning flows here; release flows through QE.**
